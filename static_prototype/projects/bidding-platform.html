Real-Time Auction & Bidding Engine

Building a sub-second bid validation engine with WebSocket broadcasting, state machine rules, and race condition settlement logic.

My Role Real-Time Backend Engineer
Protocol WebSockets (WSS)
Latency Goal < 50ms Broadcast
State Engine Redis Lua Scripts

1. Problem Statement

Online auctions closing in the final 10 seconds experience heavy "sniping" traffic. When dozens of bids arrive within the same 50ms window, the system must deterministically validate bid increments, reject stale bids, extend the timer, and broadcast the new highest bid to all connected clients.

2. Atomic Bid Validation via Redis Lua

To prevent race conditions without locking the entire SQL database, we encapsulated the comparison and broadcast publish inside a single-threaded Redis Lua script.

-- Redis Lua Script executing atomically on server
local current_bid = tonumber(redis.call('GET', KEYS[1]) or '0')
local new_bid = tonumber(ARGV[1])
local user_id = ARGV[2]

if new_bid > current_bid then
  redis.call('SET', KEYS[1], new_bid)
  redis.call('PUBLISH', KEYS[2], cjson.encode({bid = new_bid, user = user_id}))
  return 1
else
  return 0
end

3. Outcomes

  • Achieved atomic sub-10ms bid evaluation using single-threaded Redis Lua scripts.
  • Maintained stable WebSocket connection pools across 2,000+ simultaneous watchers per auction room.
