Optimizing Django & Wagtail CMS for Enterprise Scale: Queries, Caching & StreamFields

How to structure custom Page Models, avoid N+1 ORM bottlenecks, cache StreamField blocks with Redis, and maintain fast response times in production.

1. Introduction

Wagtail is one of the most elegant enterprise content management systems built on Django. However, out-of-the-box setups frequently suffer from query bloat when authors nest multiple foreign key relationships, image renditions, and polymorphic StreamFields inside deep page trees.

2. Structuring Performant StreamField Blocks

Instead of storing nested model relationships directly inside StreamField JSON blocks, store lightweight IDs or use Wagtail's built-in PageChooserBlock with deferred queryset evaluation.

3. Eliminating N+1 Queries in Django Wagtail Templates

When iterating over child pages or related image renditions, always override get_context on your parent model to eager-load relations with select_related and prefetch_related.

# Optimized Wagtail Page get_context
def get_context(self, request):
  context = super().get_context(request)
  context['articles'] = (
    ArticlePage.objects.live()
    .child_of(self)
    .select_related('author', 'featured_image')
    .prefetch_related('categories')
  )
  return context

4. Redis Cache Strategies

Combine Django's template fragment caching with Wagtail's cache invalidation hooks. Whenever a page is published or unpublished, Wagtail automatically triggers signal handlers that purge targeted Redis cache keys.

5. Key Takeaways

  • Never call related objects inside Django template loops without prefetching.
  • Profile page execution using Django Debug Toolbar or Silk before optimizing.
  • Use StreamField JSON blocks for structured components and store relational pointers cleanly.
